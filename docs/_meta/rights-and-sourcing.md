# Rights and Sourcing

This project is meant to be freely available. That only works if rights are handled from the beginning.

This page is project guidance, not legal advice.

## Collection Boundary

The project does not use broad scraping, topic crawling, or automated harvesting as a collection method. Tools may help inspect a named source, but they should not decide what belongs in the book.

Every source should have an editorial reason for inclusion before extraction work begins.

## Preferred Material

- Public-domain texts.
- Government records that are public domain in the relevant jurisdiction.
- Creative Commons licensed material that permits reuse.
- Open-access scholarship with an explicit license.
- Original commentary written for this project.

## Use With Care

- Copyrighted books, articles, translations, images, songs, and lectures.
- Modern editions of old works with new introductions, notes, translations, or editorial apparatus.
- Internet Archive items whose metadata does not clearly establish public-domain or open-license status.
- Museum and library images with item-specific restrictions.

## Excerpt Rules

Before adding copied text, record:

- Source URL.
- Edition or translation.
- Publication date.
- Rights status.
- Evidence for that status.
- Who checked it and when.

If rights are unclear, summarize instead of excerpting.

## Private Workspace Mode

The local site can also function as a private knowledge base. In that mode, restricted source material may be kept in ignored working directories or local-only notes for personal study, but it should remain clearly marked as private.

Private notes should still record source, edition, page, and rights status. That keeps future public promotion possible without rebuilding provenance from memory.

Do not deploy private notes publicly unless the copied material has been removed, summarized, or rights-cleared.

## Public Promotion

Promotion means moving material from private study into a page that could be publicly deployed. Promotion is not automatic just because a page is in `docs/` or the MkDocs build succeeds.

Before promotion, every source-derived item needs a recorded decision:

| Use | Requirement |
| --- | --- |
| Citation only | Stable citation and enough edition metadata for a reader to find it. |
| Summary or paraphrase | Citation plus a clear boundary between project prose and source claims. |
| Short quotation | Citation, edition, page/location, rights evidence, and a deliberate reason for quoting. |
| Long quotation or reproduced apparatus | Explicit public-use basis or permission; otherwise keep private. |
| Image or scan | Creator/archive/source URL, item-level rights statement, and allowed reuse terms. |

If rights are uncertain, the default public behavior is citation and summary, not quotation.

## Public Domain Is Jurisdictional

A work can be public domain in one country and copyrighted in another. Because this project is currently maintained in the United States, record U.S. rights status at minimum. Add other jurisdictions when relevant.

## Translations

Old originals can be public domain while modern translations are copyrighted. Treat translations as separate works with their own rights status.

## Images

Use images only when the item page provides a clear rights statement. Record image creator, archive, URL, and rights note.

## Recommended Original-License Decision

Before launch, choose a license for original project prose and metadata. The current recommendation is:

- Original prose: Creative Commons Attribution-ShareAlike 4.0.
- Structured metadata: CC0 or Creative Commons Attribution 4.0.
- Quoted sources: retain their original rights status.
