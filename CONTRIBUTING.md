# Contributing

This project is built around careful sourcing. A useful contribution does not need to be long, but it does need to be traceable.

## Good Contributions

- A public-domain or openly licensed source with a clear link.
- A short excerpt entry with rights status, citation, and commentary.
- An event dossier that presents competing interpretations without pretending uncertainty does not exist.
- An author profile that explains why the author changes the historical frame.
- A chapter note that connects several sources into an argument.

## Before Adding Excerpts

Check `docs/_meta/rights-and-sourcing.md`. If the rights status is unclear, add the item to the research queue instead of copying text into the book.

## Entry Workflow

1. Copy a template from `docs/templates/`.
2. Fill in the metadata first.
3. Add citations as links or footnotes.
4. Add a "What this changes" section.
5. Link the entry from the relevant catalog page.

## GitHub Issues

Use GitHub issues as the durable backlog when work should survive beyond the current editing session. Open an issue when:

- a source, thinker, constellation, or historical problem needs editorial judgment before it is promoted;
- a rights question must be resolved before public publication;
- a pipeline artifact, generated manifest, validation rule, or Makefile target needs follow-up;
- a site or UI decision affects how readers navigate the book;
- a task is important but should not interrupt the work currently in progress.

Keep issues concrete. A good issue names the page, source, script, or decision at stake; explains why it matters; and defines what "done" means. Small edits that can be completed immediately do not need an issue.

## Editorial Standard

Alternative history should be rigorous. Claims should be sourced, speculation should be labeled, and narratives should make room for complexity.
